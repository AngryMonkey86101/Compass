# Сервер групп Компаса

Хранит **только зашифрованные** последние позиции участников групп. Название группы, ники и координаты шифруются на телефоне ключом группы, которого у сервера нет. Ключ передаётся только в приглашении (QR-код или ссылка, часть после `#`).

- Node.js 22.13+, без внешних зависимостей: `node:http`, `node:sqlite`, `node:crypto`.
- Данные: SQLite на томе Docker. HTTPS: Caddy (сертификат выпускается и продлевается сам).
- Сроки хранения:
  - позиция — 2 часа;
  - заявка на вступление и приглашение — 24 часа;
  - группа без новых позиций — 7 дней.
- До 15 участников в группе.
- Журналы запросов с IP-адресами не ведутся. Адрес держится только в памяти — для ограничения частоты запросов.

## Первая настройка VPS

Вариант с Ubuntu 24.04 на любом российском хостинге: Timeweb Cloud, Selectel, Yandex Cloud. Хватит минимального тарифа: 1 vCPU, 1 ГБ памяти.

1. **Домен.** Купить домен (сейчас в настройках заглушка `compass-api.example.ru`) и создать A-запись на IP сервера.
2. **Docker.** Установить Docker:
   ```bash
   curl -fsSL https://get.docker.com | sh
   ```
3. **Пользователь для выкладки** с правом запускать Docker:
   ```bash
   adduser --disabled-password deploy && usermod -aG docker deploy
   ```
4. **Ключ для GitHub Actions.** На своём компьютере выполнить `ssh-keygen -t ed25519 -f compass-deploy -C github-actions`. Содержимое `compass-deploy.pub` добавить на сервере в `/home/deploy/.ssh/authorized_keys`.
5. **Настройки сервера.** На сервере:
   ```bash
   mkdir ~deploy/compass-server
   ```
   Положить туда `.env` по образцу `.env.example` с настоящим доменом. Файл принадлежит пользователю `deploy`.
6. **Секреты в GitHub.** Settings → Secrets and variables → Actions:
   - `SERVER_HOST` — IP сервера;
   - `SERVER_USER` — `deploy`;
   - `SERVER_SSH_KEY` — содержимое закрытого ключа `compass-deploy`;
   - `SERVER_KNOWN_HOSTS` — вывод `ssh-keyscan <IP сервера>`.
7. **Фаервол.** Открыть только порты 22, 80 и 443 (`ufw allow 22,80,443/tcp && ufw allow 443/udp && ufw enable`).

После этого каждый пуш с изменениями в `server/` проверяется тестами и собирается, а пуш в `main` ещё и выкладывается на сервер автоматически (workflow `.github/workflows/server.yml`).

**Адрес сервера для приложения.** Указывается при сборке приложения в переменной `VITE_GROUPS_API_URL`, например `https://compass-api.example.ru`. Пока она пустая, раздел «Группы» в приложении скрыт.

## Локальный запуск и тесты

```bash
cd server
npm test                         # интеграционные тесты API (node:test, без зависимостей)
DB_PATH=:memory: npm start       # сервер на http://localhost:8080
```

## API (кратко)

Всё по адресу `/api/v1`. Авторизация участника: `Authorization: Bearer <токен>`. На сервере хранится только SHA-256 токена.

| Метод и путь | Кто | Что делает |
|---|---|---|
| `POST /groups` | любой | создать группу; идентификаторы группы и владельца создаёт телефон |
| `GET /groups/:g` | участник | состояние: участники, зашифрованные позиции, время сервера; владельцу — заявки и приглашения |
| `PUT /groups/:g/position` | участник | своя позиция (409, если ключ группы сменился) |
| `DELETE /groups/:g/position` | участник | перестать передавать: позиция удаляется сразу |
| `POST /groups/:g/invites` | владелец | приглашение на 24 часа |
| `POST /join` | любой с приглашением | заявка на вступление; в ответе секрет для проверки решения |
| `GET /join/:member` | заявитель | решение; токен одобренного участника отдаётся один раз |
| `POST /groups/:g/requests/:m/approve`, `DELETE …/requests/:m` | владелец | принять или отклонить заявку |
| `POST /groups/:g/rotate` | владелец | исключить участника со сменой ключа — одной транзакцией |
| `DELETE /groups/:g/members/me` | участник | выйти из группы (ключ не меняется) |
| `DELETE /groups/:g` | владелец | удалить группу |
